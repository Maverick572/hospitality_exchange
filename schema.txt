SEEKER SEARCH DYNAMIC DATA SCHEMAS
===================================

SeekerSearchRequest:
  - description: string (Natural language requirement query)
  - fromTimestamp: string | null (ISO format or YYYY-MM-DD)
  - toTimestamp: string | null (ISO format or YYYY-MM-DD)
  - location: { address, latitude, longitude } | null (Seeker delivery location)

SeekerSearchResponse:
  - parsedItems[]: [ { category, name, quantity } ]
  - totalFound: integer
  - results[]:
      - resourceId: string
      - providerId: string
      - name: string
      - category: string
      - description: string
      - quantity: number
      - availableQuantity: number
      - price: number
      - pricingUnit: string
      - location: { address, latitude, longitude }
      - provider: { userId, businessName, rating, totalRatings, location }
      - distanceKm: number | null
      - availabilityScore: number
      - status: string

MATCHING FLOW
=============

1. Seeker Search Flow:
Natural Language Query + Timestamps + Seeker Location
    |
    v
FastAPI Seeker Engine
    |
    +-- LLM Parser (Groq / Gemini) extracts structured items & quantities
    |
    +-- Retrieve matching active Resources from Firestore
    |
    +-- Resolve provider & product geo-coordinates
    |
    +-- Calculate date availability score, pricing, and Haversine distance
    |
    v
Ordered Results (Sorted by: 1. Best Availability, 2. Lowest Price, 3. Nearest Location)

2. Logistics Route Matching Flow:
Provider Location (Pickup) + Seeker Location (Delivery) + Required Capacity + Travel Date
    |
    v
FastAPI Logistics Engine
    |
    +-- Retrieve active driverRoutes with compatible travelDate and availableCapacity
    |
    +-- Compute waypoint detour distances (Pickup & Delivery) via Haversine
    |
    +-- OR-Tools CP-SAT Solver (Optimizes detour distance, price, capacity fit, directional order)
    |
    v
Ranked Driver Routes with Detours & Fit Metrics

Firestore should store the actual business state:
resources, requirements, requests, bookings, routes,
payments, reviews, etc.

The matching and search results are dynamically computed and returned in API responses.
