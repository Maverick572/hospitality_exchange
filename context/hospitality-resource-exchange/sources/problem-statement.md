# Problem Statement (HackCelestial 3.0)

Original hackathon problem statement for this project. Provided by the user directly (not a web source).

## Key claims

- [stated] Hospitality businesses experience a resource mismatch: unused banquet space, parking, vehicles, kitchen capacity, furniture, and AV equipment sit idle at one business while another needs the same resource temporarily.
- [stated] Current discovery/access relies on personal contacts, phone calls, WhatsApp groups, brokers, or repeated enquiries — resulting in underutilized assets, unnecessary rental/procurement costs, last-minute shortages, and inefficient resource management.
- [stated] Providers must be able to: list resources (type, quantity, capacity, location, availability, pricing, conditions), define availability and prevent conflicting bookings, receive/manage requests, and accept/reject/negotiate.
- [stated] Seekers must be able to: search or post requirements (quantity, location, date/time, budget, capacity, constraints), discover/compare resources across multiple providers, submit requests, and track fulfilment status.
- [stated] Practical challenges to address: real-time availability, scheduling conflicts, location/distance, pricing, quantity, resource compatibility, minimum rental periods, transportation/logistics, request prioritization.
- [stated] Intelligent matching should rank resources/suppliers by price, distance, availability, suitability, urgency, and business preferences.
- [stated] Optional/exploratory features suggested: business profiles, ratings and reviews, quotation requests, negotiation, notifications, booking calendars, transaction tracking, resource utilization analytics, dashboards.
- [stated] Challenge is explicitly open-ended — no fixed required feature list beyond the "should be able to" items above.
